SWITCH OPERATIONS & LAYER 2 ATTACKS
===============================================================================

SWITCH FUNCTIONS

Primary Functions

- Build MAC Address Table
- Forward Ethernet Frames

-------------------------------------------------------------------------------

CAM TABLE

CAM = Content Addressable Memory

Purpose

- Store MAC -> Port mappings
- Enable fast frame forwarding

Example

AA:BB:CC:DD:EE:FF -> Fa0/1

-------------------------------------------------------------------------------

FRAME FORWARDING

Known Destination MAC

- Forward only to destination port

Unknown Destination MAC

- Flood all ports except source port

Broadcast

- Flood all ports except source port

Multicast

- Flood all ports unless IGMP Snooping or CGMP is enabled

===============================================================================
SWITCHING MODES
===============================================================================

STORE-AND-FORWARD

Process

- Receives entire frame
- Verifies FCS/CRC
- Checks for errors
- Forwards frame

Advantages

- Error detection
- Supports different interface speeds

Disadvantages

- Slowest switching method

-------------------------------------------------------------------------------

CUT-THROUGH

Process

- Reads destination MAC
- Immediately forwards frame

Advantages

- Fastest method
- Lowest latency

Disadvantages

- No error checking
- Requires same interface speeds

-------------------------------------------------------------------------------

FRAGMENT-FREE

Process

- Reads first 64 bytes
- Drops runt frames

Advantages

- Faster than Store-and-Forward
- Prevents collision fragments

-------------------------------------------------------------------------------

ETHERNET MINIMUM FRAME SIZE

Minimum Ethernet Frame

64 Bytes

Calculation

46 Byte Payload
+
18 Byte Header/Trailer
=
64 Bytes

Frames Smaller Than 64 Bytes

- Runt Frame
- Collision Fragment
- Dropped

===============================================================================
CAM TABLE OVERFLOW ATTACK
===============================================================================

Also Known As

- MAC Flooding Attack

Goal

- Exhaust CAM table memory
- Force switch to flood traffic

Result

- Switch behaves like a hub
- Increased packet visibility
- Possible MITM attack
- Possible DoS condition

-------------------------------------------------------------------------------

ATTACK PROCESS

1. Send thousands of fake MAC addresses
2. CAM table fills
3. Legitimate MAC entries removed
4. Switch floods traffic
5. Attacker captures packets

-------------------------------------------------------------------------------

MITIGATION

Port Security

switchport port-security
switchport port-security maximum 1
switchport port-security violation shutdown

VLAN HOPPING ATTACKS
===============================================================================

PURPOSE

- Access traffic on other VLANs
- Bypass Layer 3 routing controls

===============================================================================
SWITCH SPOOFING
===============================================================================

METHOD

- Pretend to be a switch
- Negotiate trunk using DTP

RESULT

- Gain access to trunk traffic
- Access multiple VLANs

-------------------------------------------------------------------------------

MITIGATION

switchport mode access

switchport nonegotiate

===============================================================================
TAGGING ATTACK
===============================================================================

METHOD

- Manually insert 802.1Q VLAN tag
- Send tagged frames from access port

RESULT

- Traffic forwarded into another VLAN

===============================================================================
DOUBLE TAGGING ATTACK
===============================================================================

REQUIREMENTS

- Knowledge of Native VLAN
- Vulnerable switch

-------------------------------------------------------------------------------

PROCESS

1. Add Native VLAN tag
2. Add target VLAN tag
3. First switch strips Native VLAN tag
4. Second tag remains
5. Frame enters target VLAN

-------------------------------------------------------------------------------

MITIGATION

switch(config)# vlan dot1q tag native

switchport mode access

switchport nonegotiate

switchport trunk native vlan 999
