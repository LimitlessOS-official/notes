 LAYER 4 — THE TRANSPORT LAYER
========================================================================================================================

 ─────────── [ 3.1 & 3.1.1 TRANSPORT PROTOCOL DIALECTICS ] ───────────

  ● TCP (Transmission Control Protocol) [cite: 631]
    ├─ PDU Typology      : Segment[cite: 633].
    ├─ Operational Style : Connection-oriented, unicast-only architecture[cite: 631, 644].
    └─ Core Mechanisms   : Demands a explicit 3-way handshake before execution[cite: 644, 689]. Provides robust error 
                           detection, byte sequencing, window-driven flow control, and formal delivery verification 
                           via explicit acknowledgments[cite: 627, 631, 645].

  ● UDP (User Datagram Protocol) [cite: 635]
    ├─ PDU Typology      : Datagram[cite: 637].
    ├─ Operational Style : Connectionless, low-overhead transmission engine[cite: 635, 636]. Can handle Broadcast, 
                           Multicast, and Unicast traffic streams seamlessly[cite: 647].
    └─ Core Mechanisms   : No session handshake, packet sequencing, or flow-control loops[cite: 635, 638, 648]. Integrity 
                           is checked via an optional IPv4 checksum (mandatory under IPv6)[cite: 648, 846]. Reliability 
                           responsibilities are deferred to application-layer logic[cite: 648].


 ─────────── [ 3.1.2 ADDR LOGIC: IANA PORT CLASSIFICATIONS ] ───────────

  ● Multiplexing & Demultiplexing: Ports let multiple apps share a single network interface[cite: 655]. The OS uses the 
    destination port value to demultiplex arriving frames, directing the binary payload to the matching listening 
    socket descriptor[cite: 656].
  ● Socket Binding: Server-side sockets execute a bind routine combining a specific IP address and listening port 
    number, advertising an accessible point of entry for clients to target[cite: 677].


 ─────────── [ 3.1.3 TCP LIFE CYCLE & RELIABILITY STATE MACHINE ] ───────────

  [ PHASE 1: 3-WAY HANDSHAKE CONNECTION ESTABLISHMENT ] [cite: 689]
    1. CLIENT ───[ SYN ]───────────────────────────────────────────────► SERVER
       │          Flags: SYN=1, ACK=0[cite: 690, 691].
       │          SEQ  : Client Initial Sequence Number (ISN)[cite: 690].
       │          Opts : Maximum Segment Size (MSS), Window Scale, SACK Permitted[cite: 693, 694, 695].
       ▼
    2. CLIENT ◄──[ SYN-ACK ]──────────────────────────────────────────── SERVER
       │          Flags: SYN=1, ACK=1[cite: 696, 697].
       │          SEQ  : Server ISN | ACK: Client ISN + 1[cite: 696, 697].
       │          Opts : Echoes supporting parameters back to the client[cite: 698].
       ▼
    3. CLIENT ───[ ACK ]───────────────────────────────────────────────► SERVER
                  Flags: SYN=0, ACK=1[cite: 699, 701].
                  SEQ  : Client ISN + 1 | ACK: Server ISN + 1[cite: 699, 700].
                  State: Connection shifts to ESTABLISHED on both sides[cite: 701].

  [ PHASE 2: ACTIVE DATA EXCHANGE ] [cite: 702]
    ● Bi-directional communication uses PSH-ACK and ACK frames[cite: 701, 704, 709].
    ● Data size tracking is managed explicitly by byte counting, updating the sequence space for every byte 
      transmitted across the channel[cite: 726].

  [ PHASE 3: 4-WAY GRACEFUL CONNECTION TERMINATION ] [cite: 710]
    1. INITIATOR ───[ FIN-ACK ]───► RECEIVER   (Signals initiator has no more data to write)[cite: 712, 781].
    2. INITIATOR ◄──[ ACK ]───────  RECEIVER   (Receiver acknowledges the initiator's FIN request)[cite: 714].
    3. INITIATOR ◄──[ FIN-ACK ]───  RECEIVER   (Receiver issues its own shutdown request)[cite: 715].
    4. INITIATOR ───[ ACK ]───────► RECEIVER   (Final verification; channel enters TIME-WAIT)[cite: 719, 805].

  ● CONTROL FLAGS MAP (Byte 13 / Bits 104-111) [cite: 731]
    ┌─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┐
    │ CWR │ ECE │ URG │ ACK │ PSH │ RST │ SYN │ FIN │
    │ 128 │  64 │  32 │  16 │  8  │  4  │  2  │  1  │ ← Bit Multipliers [cite: 786]
    └─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┘
    ├─ SYN     (0x02): Initializes sequence numbers for new connections[cite: 761, 786].
    ├─ SYN/ACK (0x12): Server's response confirming connection parameters[cite: 786].
    ├─ ACK     (0x10): Validates the acknowledgment number field[cite: 728, 786].
    ├─ PSH/ACK (0x18): flushes buffers directly to the application layer[cite: 777, 786].
    ├─ RST/ACK (0x14): Abruptly aborts ungraceful or invalid connections[cite: 778, 786].
    └─ FIN/ACK (0x11): Initiates normal connection teardown[cite: 781, 786].

  ● CRITICAL TCP STATE DEFINITIONS
    ├─ LISTEN        : Server is waiting for connection requests on an open port[cite: 795].
    ├─ SYN-SENT      : Sent a connection request, waiting for a matching response[cite: 796].
    ├─ SYN-RECEIVED  : Received and sent connection requests, waiting for final ACK[cite: 797].
    ├─ ESTABLISHED   : Active connection, data can be transferred reliably[cite: 798, 799].
    ├─ FIN-WAIT-1    : Sent a termination request, waiting for ACK or remote FIN[cite: 800].
    ├─ FIN-WAIT-2    : Remote peer acknowledged our FIN, waiting for their FIN[cite: 801].
    ├─ CLOSE-WAIT    : Remote peer closed, local application has not terminated yet[cite: 802].
    ├─ CLOSING       : Simultaneous close, waiting for remote termination ACK[cite: 803].
    ├─ LAST-ACK      : Received remote FIN, sent local FIN, waiting for final ACK[cite: 804].
    ├─ TIME-WAIT     : Waiting to ensure remote peer received the final close ACK[cite: 805].
    └─ CLOSED        : Idle state; no active network connection exists[cite: 806].

  ● ADVANCED OPTIONS ENGINE (Kinds 0-15)
    ├─ Kind 0 : End of Options List. Delimits option parsing routines[cite: 807].
    ├─ Kind 1 : No-Operation (NOP). Multi-byte word padding to ensure alignment on 32-bit boundaries[cite: 808, 810].
    ├─ Kind 2 : Maximum Segment Size (MSS). Negotiates maximum payload bytes per frame to prevent L3 fragmentation[cite: 811, 813].
    ├─ Kind 3 : Window Scaling. Bitwise shift multiplier to scale windows up to 1GB[cite: 770, 824].
    ├─ Kind 4 : SACK Permitted. Negotiates permission for selective retransmission tracking[cite: 832].
    ├─ Kind 5 : Selective Acknowledgment (SACK). pinpoints missing blocks to avoid full retransmission[cite: 833, 834].
    ├─ Kind 8 : Timestamps. Tracks round-trip times and protects against old, delayed packets[cite: 768, 838].
    └─ K14/15 : Alternate Checksum Request/Data. Rarely used custom checksum options[cite: 839, 841].

 LAYER 5 — THE SESSION LAYER
========================================================================================================================

 ─────────── [ CORE OSI LAYER 5 ANALYSIS ] ───────────
  ● Session Management: Tracks the lifetime of active network sessions, managing their establishment, 
    maintenance, and orderly teardown[cite: 627].
  ● Key Protocols Examined[cite: 624]:
    ├─ NetBIOS (Network Basic Input Output System): Legacy API and protocols supporting naming services and session tracking.
    │  └─ Suffix System: Suffix bytes designate target network capabilities (e.g., <00> Workstation, <20> File Server).
    ├─ SOCKS Protocol: Generic proxy mechanism that routes raw TCP/UDP streams transparently across boundary points.
    └─ RPC (Remote Procedure Call): Client-server protocol allowing applications to run code on remote systems as if it 
       were local[cite: 296, 298].
  ● RPC vs API Distinctions[cite: 624]:
    ├─ RPC (Remote Procedure Call) is a strict communication protocol designed to execute functions across network 
    │  boundaries, abstracting away underlying network implementation details[cite: 296, 298].
    └─ API (Application Programming Interface) is a broader concept defining interaction contracts and data structures[cite: 299, 300]. 
       APIs can use various formats, including RESTful HTTP, SOAP, or GraphQL[cite: 304].

 LAYER 6 — THE PRESENTATION LAYER
========================================================================================================================

 ─────────── [ PRESENTATION LAYER CORE FUNCTIONS ] ───────────
  ● Responsibilities: Translates data between local application logic and standard network transfer structures, 
    managing character encoding, compression, and encryption/decryption tasks[cite: 307, 316].

  ● Character Encodings & System Archetypes[cite: 310, 318, 321, 333]:
    ├─ ASCII        : 7-bit framework mapping standard English characters to values from 0–127[cite: 310, 318, 319].
    ├─ CP437        : Legacy 8-bit IBM PC system incorporating box-drawing symbols[cite: 333, 334].
    ├─ Unicode      : Universal code point registry mapping more than 137,000 global characters and symbols[cite: 321, 322].
    ├─ UTF-8        : Variable-width system using 1 to 4 bytes per character; standard for modern web traffic[cite: 323, 324].
    └─ Base64       : Translates raw binary into printable ASCII characters for safe transmission over text protocols[cite: 327].

  ● Mojibake (Garbled Text): Occurs when bytes are decoded using a different character encoding scheme than the one used 
    to encode them[cite: 311, 314]. It represents a syntax misinterpretation problem, not underlying data loss[cite: 311, 312].

  ● Data Transformation Typology[cite: 313, 315]:
    ├─ Encoding    : Algorithmic transformation to guarantee data compatibility and readability across diverse platforms[cite: 313].
    ├─ Encryption  : Scrambles plaintext into ciphertext using cryptographic keys to preserve data confidentiality[cite: 315].
    └─ Compression : Optimizes network utilization by shrinking file sizes using lossless or lossy data reduction math[cite: 315].
